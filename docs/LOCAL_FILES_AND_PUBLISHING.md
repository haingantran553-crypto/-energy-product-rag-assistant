# 本地资料与GitHub发布范围

不需要删除已跑通项目中的资料。把“原项目工作目录”和“干净发布目录”分开即可。

## 两个目录各做什么

- 原项目：D:\AIProject\rag-from-scratch\rag-from-scratch-main。继续用于本机运行、真实资料问答、历史恢复和保存失败证据。原备份、旧知识库、历史、.env和虚拟环境全部保留。
- 发布目录：D:\AIProject\energy_product_rag_v661_candidate（将候选包解压到此独立目录）。只放当前代码、说明、依赖、示例、经过整理的评测摘要和忽略规则。

不要把整个原项目复制过去再上传，也不要从原目录直接全选上传。

| 内容 | 本地处理 | GitHub范围 |
| --- | --- | --- |
| 当前6个应用模块、自检脚本、README、依赖和来源说明 | 原项目与发布目录分别保留对应版本 | 使用候选包中整理好的文件 |

## 知识库和历史不上传，别人如何运行

新使用者自行安装依赖、配置自己的.env、下载公开说明书并创建自己的知识库。本项目发布的是代码与复现说明，不是作者已经使用过的本地数据目录。

你自己继续运行原目录时，仍能打开原知识库并恢复历史，不受发布目录影响。此次不要求搬迁知识库，也不要求再次建库或问答。

## 提交前如何看范围

使用Git时，在干净发布目录检查：

```powershell
git status
git diff --cached --name-only
```

待提交列表不应出现.env、_local_kb、_backups、虚拟环境、PDF、SQLite、qa_records原始文件或Notebook。候选包.gitignore包含这些本地目录与常见数据文件的忽略规则。

网页手动上传也只选择干净发布目录里的文件。不要把忽略规则当作从原项目全选上传的过滤器；已经提交的文件也不会因后来增加.gitignore自动从Git历史移除。若发现范围不对，先停下检查，不通过删除本地唯一资料解决。
