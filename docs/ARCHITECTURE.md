# 技术结构

上传PDF/TXT→解析与350/60切块→命名知识库新版本→本地保存原资料/块/Chroma索引。写入失败不切换原可用版本，打开时检查嵌入身份、Chroma版本与完整性；BM25从保存的块重建。

提问先在当前库/版本/对话内有限补全。完整问题保持原文；规则只从上一问题继承明确主题，不从旧答案继承产品数值；无法确定则澄清且不调用检索/聊天。

检索：一次全局向量查询最多6个候选，每文件BM25按全文/有限字段线索打分，融合每文件最多3个种子块，补同文件同页邻块，去重，总候选正文预算12000字符。单位字段规则只补参数类型，不生成答案数值。

生成：模型中文回答并标编号。保留原文和编号，分组显示实际引用/其他候选。有限数值检查发现疑点时，最多一次额外生成；提供首次回答与同文件数值原文定位。只有可检测疑点严格减少、不新增、已有引用包含的数值项目未删时才采纳，纯通用拒答保守允许。失败或不改善则保留首次输出和警告。

归档：最终答案、候选、原问题/检索问题、首次与校正原文、采纳决定、模型调用数、单次耗时、代码/资料哈希及批次写入SQLite。评分可修订、原始问答不可当评分字段改写；修订冲突拦截。保存失败保留会话对象并提示重试/下载，不重新调用模型。旧记录不补写新版本字段。

只保存白名单，不持久化真实API密钥、接口地址或内部配置签名。问答和资料原文仍属于本地数据，公开前另行整理。不同库/版本切换隔离索引和聊天；历史按所属库/版本恢复。权限体系、多用户并发及生产运维尚未实现。
